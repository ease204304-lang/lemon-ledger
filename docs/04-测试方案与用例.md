### 9.2 缺陷生命周期状态机

```text
新建(New) → 已确认(Confirmed) → 已分配(Assigned) → 修复中(In Progress)
   → 已修复(Fixed) → 待验证(Ready for Test) → 已验证(Verified) → 已关闭(Closed)
                                  ↘ 验证不通过(Reopened) → 已分配
任意状态 → 已拒绝(Rejected)（附理由：不可复现 / 非缺陷 / 需求如此，需 QA Lead 与产品共同确认）
任意状态 → 已延期(Deferred)（须在 RTM 与风险登记册同步登记，并给出规避方案）
```

| 状态 | 准入条件 | 出口 |
|---|---|---|
| 新建 | 提交人按 §9.3 模板填写完整 | 被确认或被拒绝 |
| 已确认 | QA Lead 复现成功并定级 | 分配给开发者 |
| 修复中 | 开发者已受理 | 提交修复构建 |
| 已修复 | 有构建号与影响范围说明 | 进入回归 |
| 已验证 | 原用例 + 关联用例（黄金算例、`UI` 项）回归通过 | 关闭 |
| 已拒绝 | 给出可核查理由 | 归档，必要时转需求变更 |
| 已延期 | 有规避方案与目标版本 | 进入 `03` 风险登记册 |
