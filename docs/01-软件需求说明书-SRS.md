## 2. 项目背景与产品定位

### 2.1 背景
移动端个人记账是高频、低耐心的场景：用户往往在付完款的几秒内完成一次记录，任何多余步骤都会导致弃用。市面上主流产品功能日趋臃肿（理财推荐、社区、返现、贷款导流），对「只想清楚知道钱花在哪」的个人用户形成干扰。

### 2.2 产品定位
> **一款干净、快、纯本地的个人记账工具**：打开即可看到本月收支与流水，三秒记完一笔，图表一眼看清钱花在哪，数据只在本地、可随时完整导出。

### 2.3 目标用户
- 主要：22–45 岁、有稳定收入、希望建立消费自觉但不想要理财社区的打工人与家庭记账者。
- 次要：需要给家庭开支留痕、但不希望数据上传云端的隐私敏感用户。

### 2.4 用户核心诉求（按优先级）
1. 记账要**快**——最少点击完成一笔。
2. 看账要**清楚**——本月花了多少、哪一类最花钱。
3. 数据要**在自己手里**——离线可用、可导出、可备份。

### 2.5 成功指标（v1.0 上线后 30 天观测）

| 指标 | 目标值 |
|---|---|
| 记一笔流水的平均操作步数 | ≤ 4 步（分类 → 金额 → 完成） |
| 记账页到完成的中位耗时 | ≤ 8 秒 |
| 次日留存 / 7 日留存 | ≥ 35% / ≥ 18% |
| 崩溃率 | < 0.5% |
| 冷启动时间（中端机） | < 1.5 秒 |
| 数据导出成功率 | ≥ 99.5% |

## 5. 功能需求

> 每条需求包含：描述、业务规则、验收标准（可判定）。验收标准对应 `04` 中的 TC 用例。

### 5.1 FR-1 记账流水（对应原型 `#entry`，参考图 REF-2）

#### FR-1.1 记账页入口与结构（Must）
**描述**：底部导航中间的悬浮黄色圆形 `+` 按钮进入记账页；记账页顶部为三栏结构——左「支出」（默认选中）、中「收入」、右「取消」；选中项带下划线。

**业务规则**
- `BR-1.1.1` 默认进入「支出」页签；页签切换时保留已输入金额与备注，分类按页签各自记忆。
- `BR-1.1.2` 点击「取消」直接返回来源页，未保存内容丢弃且**不弹二次确认**。
- `BR-1.1.3` 记账页为全屏页面，不显示底部导航。

**验收标准**
1. 任意页面点击底部 `+` 均进入记账页且默认选中「支出」。
2. 在「支出」输入金额并选中分类后切到「收入」，金额与备注保留，分类选中态切换为收入类记忆项。
3. 点击「取消」返回原页面，再次进入记账页输入区为初始态。

#### FR-1.2 分类网格选择（Must）
**描述**：分类以 4 列网格展示，每项为「圆形图标底 + 图标 + 下方分类名」；未选中圆底为 `#F5F5F5`，选中为 `#FFD946`。

**业务规则**
- `BR-1.2.1` 支出页签默认选中第一个分类；收入页签默认选中第一个收入分类。
- `BR-1.2.2` 网格可纵向滚动，最后一项为「更多」入口（进入分类管理）。
- `BR-1.2.3` 已停用分类不出现在网格中。
- `BR-1.2.4` 同一时刻最多只有一个选中分类。

**验收标准**
1. 网格为 4 列，首屏可见 16 个分类，分类名居中显示。
2. 点击某分类后，仅该项圆底变为 `#FFD946`、图标转为深色，其他项恢复 `#F5F5F5`。
3. 网格滚动到底可见「更多」入口，点击进入分类管理页。

#### FR-1.3 金额键盘录入（Must）
**描述**：页面底部为 4×4 数字键盘：`7 8 9 今天` / `4 5 6 +` / `1 2 3 −` / `. 0 ⌫ 完成`。金额在键盘上方右对齐显示。

**业务规则**
- `BR-1.3.1` 初始显示 `0.00`。
- `BR-1.3.2` **小数位最多 2 位**，第三位小数按键无效。
- `BR-1.3.3` 整数部分最多 9 位（上限 999,999,999.99）。
- `BR-1.3.4` 单个 `0` 开头时，输入数字替换而非拼接（`0` → 按 `5` → `5.00`）。
- `BR-1.3.5` `+` / `−` 为快捷运算键：先输入一个数、按 `+`、再输入一个数，显示区实时显示前两数之和，按「完成」时以该结果保存。
- `BR-1.3.6` `⌫` 逐位删除；删至空时显示 `0.00`。
- `BR-1.3.7` 「完成」键位于键盘第 4 行第 4 列，黄底（`#FFD946`）深色字，与其余键等高（实测参考图行高 187px，四行等分）。

**验收标准**
1. 依次点击 `1 2 . 3 4 5`，显示 `12.34`（第 3 位小数被忽略）。
2. 输入 `0` 后按 `5`，显示 `5.00`。
3. 输入 `8`、按 `+`、输入 `1`、按 `+`、输入 `8`，显示 `17.00`；点「完成」后保存金额为 `17.00`。
4. 「完成」键与普通键等高，底色为 `#FFD946`。

#### FR-1.4 备注填写（Must）
**描述**：键盘上方为浅蓝灰（`#ECF0F3`）圆角备注行，左侧固定文案「备注：」，右侧占位文案「点击填写备注」，最右为图片与标签两个图标入口。点击该行弹出输入面板。

**业务规则**
- `BR-1.4.1` 备注长度上限 50 字符，超出截断并提示。
- `BR-1.4.2` 备注为空时不写入数据，列表中回退显示分类名（见基线 `A-5`）。

**验收标准**
1. 点击备注行弹出输入面板，输入「打车」后行内显示「备注：打车」。
2. 输入 51 个字符时，实际保存 50 个字符并出现提示。

#### FR-1.5 交易日期选择（Must）
**描述**：键盘右上角「今天」键显示当前日期语义；点击弹出日期选择面板，可选过去任意日期；选择后该键文案变为所选日期。

**业务规则**
- `BR-1.5.1` 默认日期为今天。
- `BR-1.5.2` **允许选择未来日期**，但选择后需在键位与保存提示中标注（用于预付/计划类记账）。
- `BR-1.5.3` 日期以 epochDay 存储，仅取本地日历日，不做时区换算。

**验收标准**
1. 默认「今天」键显示当天日期语义，保存的流水日期为当天。
2. 选择 `2026-10-05` 后，「今天」键文案变为 `10-05`，保存后该流水出现在明细页 10-05 分组内。

### 5.4 FR-4 数据备份与导出（对应原型 `#mine`）

#### FR-4.1 本地备份（Must）

**业务规则**

**验收标准**

- `BR-4.2.3` 文件损坏、`version` 不兼容或 `checksum` 不匹配时**必须拒绝导入**并给出明确原因，不得部分写入。

**验收标准**
1. 覆盖恢复后数据与备份时完全一致（条数、金额、日期、备注一致）。
2. 选择损坏文件时提示「备份文件已损坏，无法恢复」，本地数据保持原样。
3. 使用更高版本号的文件时提示版本不兼容。

#### FR-4.3 CSV 导出（Must）
**描述**：按所选时间范围导出 UTF-8（含 BOM）的 CSV 文件。

**业务规则**
- `BR-4.3.1` 列定义固定为：`日期,类型,分类,金额,备注,标签,创建时间`。
- `BR-4.3.2` 金额导出为 2 位小数的正数，类型列区分「支出/收入」。
- `BR-4.3.3` 含逗号、引号、换行的字段按 RFC 4180 转义。
- `BR-4.3.4` 记录数 ≤ 1000 时可选择直接分享，超过时保存文件。

**验收标准**
1. 用 Excel 打开导出的 CSV，中文不乱码，列与 `BR-4.3.1` 一致。
2. 备注含 `,` 与 `"` 的记录导出后被正确转义，重新导入不串列。

#### FR-4.4 Excel(.xlsx) 导出（Should）
**描述**：导出 `.xlsx`，首个工作表名 `流水`，列同 CSV，表头加粗。

**验收标准**：生成的文件可被 Excel/WPS 正常打开，首行表头加粗，数值列为数字格式而非文本。

#### FR-4.5 云同步（Won't(v1.0) → v1.1）

**验收标准**：v1.0 该入口置灰并标注「后续版本提供」；架构评审确认 Repository 接口已抽象。

#### FR-6.1 通用设置（Should）

1. 开启密码锁后冷启动进入解锁页。
2. 连续 5 次错误密码后出现 60 秒倒计时，期间无法输入。
3. 忘记密码时可通过重装清空数据（明确提示该后果）。

#### FR-6.3 关于与版本（Could）
**描述**：显示应用名、版本号、开源许可、隐私说明、备份提示。

**验收标准**：显示版本号与「数据仅保存在本机」的隐私说明文案。

#### FR-6.4 发现页与我的页（Could）
**描述**：发现页为功能占位（不做内容运营）；我的页集中承载 FR-4 / FR-5 / FR-6 的入口。

**验收标准**：发现页显示「更多功能开发中」；我的页包含备份与导出、分类管理、标签管理、设置、关于五个入口。

## 7. 数据需求

### 7.1 实体与关系
```text
Ledger(默认账本) 1 ── n Transaction n ── 1 Category
                                n ── m Tag
AppSetting(单例表)
```
字段定义以 [`docs/00-基线与术语.md`](00-基线与术语.md) §6 为准。

### 7.2 精度与一致性规则
- 金额：`Long` 分。所有合计、占比、平均值计算在整数域完成，仅在格式化时转为小数字符串。
- 日期：`Int` epochDay（本地日历日）。禁止将 UTC 时间戳直接当日期使用。
- 一致性：编辑/删除流水后，明细合计、日小计、图表统计必须同源重算，不允许各页各自缓存。

### 7.3 初始数据
支出分类 20 项、收入分类 7 项，取值与顺序见基线 §8。首次启动自动写入，并标记 `isBuiltin=true`。

### 7.4 数据规模假设
- 单用户 3 年使用量约 3000–10000 条，设计上限按 10 万条验证查询与统计性能。

### 7.5 数据保留与删除
- 软删除保留 30 天，之后由「清理回收站」操作物理删除（用户在设置中手动触发，不自动静默删除）。

## 9. 接口需求

### 9.1 备份文件格式（单文件 JSON）
```json
{
  "meta": { "version": 1, "exportedAt": "2026-10-09T22:10:15+08:00", "deviceModel": "...", "appVersion": "1.0.0", "checksum": "<sha256>" },
  "settings": { "currencySymbol": "¥", "weekStart": "MONDAY", "defaultEntryType": "EXPENSE", "hideAmount": false },
  "categories": [ { "id": 1, "name": "餐饮", "type": "EXPENSE", "iconKey": "food", "parentId": null, "sortOrder": 2, "isActive": true } ],
  "tags": [ { "id": 1, "name": "出差" } ],
  "transactions": [ { "id": 1001, "type": "EXPENSE", "amountCents": 1500, "categoryId": 1, "tagIds": [1], "tradeDateEpochDay": 20731, "note": "午餐", "photoUris": null, "createdAt": 1790000000000, "updatedAt": 1790000000000, "deletedAt": null } ]
}
```
- `checksum` = 对除 `meta.checksum` 外的全部内容做 SHA-256。
- 恢复时**先校验后写入**，`version` 高于当前支持版本直接拒绝。

### 9.2 导出列定义

| 序号 | 列名 | 类型 | 说明 |
|---|---|---|---|
| 1 | 日期 | `YYYY-MM-DD` | 交易日期 |
| 2 | 类型 | 文本 | `支出` / `收入` |
| 3 | 分类 | 文本 | 二级分类时形如 `交通/停车费` |
| 4 | 金额 | 数值(2 位小数) | 正数 |
| 5 | 备注 | 文本 | RFC 4180 转义 |
| 6 | 标签 | 文本 | 多标签以 `|` 分隔 |
| 7 | 创建时间 | `YYYY-MM-DD HH:mm:ss` | 本地时间 |

### 9.3 云同步预留接口（v1.1）
数据访问层需暴露与实现无关的抽象，v1.0 仅落地本地实现：
```text
TransactionRepository: list(month) / get(id) / insert(tx) / update(tx) / softDelete(id) / restore(id)
CategoryRepository:    list(type) / insert / update / setActive
BackupService:         backup(target) / restore(source, mode) / exportCsv(range) / exportXlsx(range)
```
