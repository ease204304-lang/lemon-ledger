## 一、结论摘要

| 维度 | 结论 |
|---|---|
| 需求规模 | T01–T34 共 34 个用例, 涉及 3 视图 / 7 类统计 / 6 大数据模型实体 / 7 个 API 契约 |
| 现有实现 | 5 屏本地应用, 无服务端、无账本、无交易对象、分类单级、标签单角色 |
| **可验证比例** | **34 个用例中, 本地 App 可直接验证约 9 个 (26%)** |
| 阻塞原因 | ① 文档以服务端 API 为基线 (7 个 REST 接口 + 快照版本 + 鉴权) ② 账本/对象/两级分类/主辅标签 4 个实体完全缺失 ③ C140 性能验收需 5 万笔 + 指定环境 |

## 二、数据模型差距 (技术说明 01)

| 实体 | 文档要求 | 现有实现 | 差距 |
|---|---|---|---|
| AccountBook 账本 | id/name/成员权限, 统计隔离边界 | ❌ 无 | **缺整表** — T12 账本隔离无法测 |
| Transaction | 9 字段 (含 currency/date/time/counterparty/updated_at) | 7 字段 (`tx` 表) | 缺 counterparty_id、currency、transaction_time、updated_at |
| Category | **固定两级** (parent_id/type/status/名称快照) | **单级** (id/name/icon_key/type/sort_order/archived/pinned) | ❌ 无 parent_id → T07 父子去重无法测 |
| Tag + TransactionTag | 标签含 scope(收支适用); 关联含 **role(主/辅)** | Tag 无 scope; tx_tag 无 role | ❌ 主/辅标签缺失 → T15/T23 无法测 |
| Counterparty | 独立表 + 合并/拆分映射 + 审计 | ❌ 无 | **缺整表** → T17/T18 无法测 |
| 版本与缓存 | book_id/version/规范化查询键/失效时间 | ❌ 无 | 无快照版本 → T08/T09/T27 异步一致性无法测 |
| 金额校验 | amount > 0, 定点十进制 | `amount_cents INTEGER` ✓ 定点 | 缺 **> 0 校验** → T19 部分失败 |

## 三、接口契约差距 (技术说明 02)

| 接口 | 文档 | 现有 | 可否本地等价 |
|---|---|---|---|
| GET /statistics/summary | income/expense/balance/balance_rate/笔数/日均 | ❌ 无 balance/balance_rate/日均 | ⚠️ 可用 SQL 直算实现 |
| GET /statistics/trend | bucket + 同期点 + 零值填充 | ✓ 有折线 (仅周/月/年) | ⚠️ 需补 日/自定义 + 同期点 |
| GET /statistics/categories | 两级 + 排名 + 穿透键 | ⚠️ 仅一级 Top N | ❌ 缺两级 + 穿透 |
| GET /statistics/tags | 主标签环形图 + 未设置标签 | ⚠️ 有环形图 (无"未设置标签"桶) | ⚠️ 需补 |
| GET /statistics/merchants | 对象榜 | ❌ 无 | ❌ 缺实体 |
| GET /statistics/balance | 结余组合 | ❌ 无 | ⚠️ 可 SQL 直算 |
| GET /transactions + /{id} | 分页明细 + 详情 | ⚠️ 有列表无分页/详情 | ⚠️ 需补 |

## 六、结论与建议

**技术说明 07「开发前核定」明确要求**: "项目需提供数据库结构、客户端路由与状态方案、已有接口鉴权方式、当前数据分布和性能环境。产品需冻结《需求决策追踪表》中的未决规则"。

当前状态:
- ✅ 数据库结构 — 已有 (但缺 4 实体)
- ⚠️ 客户端路由与状态方案 — 现有 5 屏单路由切换, 缺统计模块的状态层
- ❌ 已有接口鉴权方式 — **无服务端, 无鉴权**
- ⚠️ 当前数据分布 — 种子 18 笔 (远低于 5 万笔性能门槛)
- ❌ 性能环境 — 无

**建议路径** (供用户决策):
1. **口径对齐先行**: 先冻结 D01–D08 未决规则 (尤其 D02 删除分类 / D05 对象合并 / D06 边界与日均 / D07 异常金额), 否则 T07/T14/T18/T32/T34 无法定验收标准
2. **可立即执行的部分**: 对 3 个 ✅ + 18 个 ⚠️ 用例中"本地可验证子集"先写自动化测试并出具结果 (占清单 60%+ 的功能面)
3. **服务端缺口决策**: 文档以 REST API 为基线, 但本项目是纯本地 App — 需确认是 (a) 本地化实现 (SQLite 直算, 保留全部计算语义), 还是 (b) 引入服务端
4. **实体补齐**: AccountBook / 两级 Category / Tag.scope + TagRole / Counterparty 是 13 个不可测用例的共同前置
